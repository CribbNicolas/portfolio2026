# 03 — CV

---

## 1. Dos versiones, no una

| Versión | Para qué | Formato |
|---|---|---|
| **CV-A** (diseñado) | WhatsApp, mail directo, cliente freelance, descarga desde el portfolio | Dos columnas, foto, color. Lo abre un humano. |
| **CV-B** (`cv-ats`) | Computrabajo, Bumeran, LinkedIn Easy Apply, cualquier formulario que pida subir archivo | Una columna, sin íconos, sin gráficos. Lo parsea una máquina. |

Mismos hechos en las dos: salen del mismo dataset, cambia la vista. En Argentina la foto se espera y un CV bien diseñado comunica criterio de producto — por eso no se tira el CV-A, se duplica.

## 2. Reglas de formato del CV-B

- Una sola columna. Sin sidebars, tablas, cajas de texto, headers ni footers.
- Secciones con nombres estándar: `Perfil`, `Habilidades técnicas`, `Experiencia`, `Educación`. Nada de "Mi stack" ni "Lo que me mueve".
- Fechas en formato consistente `MM/AAAA`.
- Sin barras de progreso ni puntitos de nivel: ningún parser los lee.
- Nombre de archivo: `Nicolas-Cribb-Barbaro-Full-Stack-Developer.pdf`.
- 1 página para startups, 2 para corporativo o LatAm tradicional.
- **Test de parseo:** abrir el PDF, seleccionar todo, pegar en un bloc de notas. Si sale desordenado, el parser lo lee igual de mal.

## 3. Perfil (3-4 líneas, arriba de todo)

```
Desarrollador Full Stack construyendo productos web end-to-end en React,
Next.js y TypeScript, con base sólida en Node, Docker y CI/CD. Llevé proyectos
desde el primer commit hasta producción, tanto solo como en equipos.
[Logro más fuerte, con número.]
```

La antigüedad no se escribe: se deriva de `careerStart`.

## 4. Bullets: el patrón

El registro de **responsabilidades** ("implementé buenas prácticas", "optimicé procesos manuales") es exactamente el que la capa humana lee como plantilla. El que funciona es **acción técnica + objeto concreto + resultado**.

Cada bullet vive en el dataset como un `Achievement` con su `dimension`. Cubrir dimensiones distintas en cada rol evita cuatro bullets que dicen lo mismo:

`delivery` · `architecture` · `performance` · `ownership` · `collaboration` · `business`

### Estado actual por rol

**Dinkum Interactive** — 4 logros cargados (mapas Mapbox, corrección de renderizado + feature-state, migración a Vite, plugins de WordPress con React/MUI/TS). Falta: al menos uno con número.

**Adsmovil** — 2 logros cargados (modernización tecnológica con React, sistemas de recolección de datos). Faltan: cantidad de productos, tamaño de equipo, impacto medible.

**Hogarth** — 1 logro cargado (versiones localizadas para cliente global). Falta: cuántos mercados o idiomas, qué mejoraste además de mantener.

**Freelance** — 1 logro cargado (optimización de delivery con build system). Faltan: cantidad de proyectos, un caso con resultado de negocio.

## 5. Métricas pendientes

Esto es el 80% del valor que falta. Un rango honesto sirve; un número inventado se cae en la entrevista.

| Logro | Qué medir |
|---|---|
| `dinkum-vite` | Tiempo de build antes/después |
| `dinkum-mapbox` | Volumen de datos o cantidad de usuarios del mapa |
| `adsmovil-datos` | Qué mejoró en la recolección: tiempo, volumen, tasa de error |
| `adsmovil-react` | Tamaño del equipo, cantidad de productos migrados |
| `freelance-build` | Peso del bundle o tiempo de carga antes/después |
| `hogarth-i18n` | Cantidad de mercados o idiomas |

Si el número es estimado: `confidence: "estimated"` y el generador lo renderiza con "~". Y llenar `source` con cómo lo sabés — no se publica, es la nota para la entrevista.

## 6. Habilidades técnicas

Agrupadas, sin niveles gráficos:

```
Lenguajes: TypeScript, JavaScript, PHP
Frontend: React, Next.js, SolidJS, Vue 3, Tailwind CSS, Material UI, Jotai
Backend y datos: Node.js, REST APIs, Sanity (headless CMS), WordPress/WooCommerce
Testing: Playwright
Infraestructura: Docker, CI/CD, Cloudflare, monorepos, Git
Otros: Mapbox GL JS, desarrollo asistido por IA (Claude Code, Cursor)
```

**Regla 3 del contrato:** ninguna skill puede declararse `core` si ningún logro o proyecto la referencia. Al cargar el dataset, el validador ya bajó `Git` de `core` a `working` por esto.

Lo que se sacó del CV viejo y por qué: `SVN` (nadie lo busca, sugiere entornos legacy), `Router`/`Query` anidados bajo React (no son herramientas de ese nivel; anidarlos comunica que no jerarquizás), `Java/Springboot` (si no lo vas a defender en entrevista, no suma).

Lo que faltaba y ahora está: **Mapbox GL JS** (antes solo aparecía como "mapas interactivos" en prosa — el término buscable es el otro), **Playwright** (testing aparece en buena parte de los avisos y separa mid de senior), **WordPress** en la lista y no solo en un bullet.

## 7. Correcciones aplicadas sobre el CV anterior

| Problema | Estado |
|---|---|
| Hogarth: "Jul 2022 - Ene 2024" con "(7 meses)" al lado — el rango son 18 meses | Corregido a 2023-07, coherente con LinkedIn. **Confirmar** |
| Hogarth y Adsmovil ambos "Jornada completa" y superpuestos | Hogarth pasó a `contract` + `concurrent: true`. **Confirmar** |
| "Sep 2024 - Actualidad (+1 año 6 meses)" — duración hardcodeada y vencida | Las duraciones se calculan siempre |
| Tres antigüedades distintas (2018 en LinkedIn, 2020 en el CV, abril 2020 en la experiencia) | `careerStart = 2020-04`, todo se deriva |
| Título "Web Developer / React Specialist" | `Desarrollador Full Stack` |
| Dirección de calle completa en el PDF | Solo ciudad y provincia; `streetAddress` nunca sale en un output |
| Typos: "desafios", "practicas", "Analísta", "Ingenierían" | Corregidos en el dataset |
| "Cliente de renombre mundial" (vago) | `clientDescription: "cliente global del sector tecnológico"` |
| Cero números en todo el documento | Pendiente — sección 5 |

## 8. Checklist por postulación (10 minutos)

1. Leer el aviso completo y anotar las 8-10 skills que menciona.
2. Chequear las variantes exactas: si dice "Vue.js", usar "Vue.js". Los `aliases` del schema permiten emitir la forma exacta sin editar datos.
3. Ajustar el bloque `Perfil` para que hable del problema del puesto.
4. Reordenar `Habilidades técnicas` poniendo primero lo que pide el aviso.
5. Elegir la superficie correcta: formulario → `cv-ats`; mail o WhatsApp → CV-A.
6. Verificar que LinkedIn diga lo mismo que el CV que estás mandando.
7. Si el portal permite mensaje, escribir 3 líneas específicas de esa empresa. Es lo que evita el 62% de descarte por falta de personalización.

**No mandar el mismo PDF a todos.** Es la diferencia entre un match del 40-60% y uno del 75%+.
